# 頁面分工與首頁

用於新增頁面、規劃導覽、重做首頁與整體改版。先分配訪客任務，再設計版面；既有品牌風格、已確認的使用者要求及本次修改範圍優先。

## 每頁只做一件事

每個內頁只承擔一個功能，以訪客要完成的任務定義。選購頁的搜尋、分類及篩選共同服務「找到商品」；購買教學、品牌歷史則是不同任務，應分頁。共同導覽、頁尾與必要的返回／下一步不算另一個功能。

首頁是入口例外：讓訪客知道為什麼選這個品牌、快速找到熱賣／精選商品，再進入商品或完整購物頁。入口可以分流，但不承載各內頁的完整內容。

## 頁面分工

| 頁面 | 唯一主要任務 | 必要內容及下一步 |
| --- | --- | --- |
| 首頁／入口 | 理解品牌選擇理由並找到購物入口 | 具體且可驗證的差異、少量熱賣／精選商品、商品捷徑、查看全部商品 |
| 完整選購 | 找到要買的商品 | 完整商品範圍、需要的分類／搜尋／篩選、商品詳情入口 |
| 商品詳情 | 判斷該商品是否合適並選購 | 真實照片、用途與購買理由、規格／價格、必要疑慮、數量及加入購物袋 |
| 怎麼買／購物說明 | 理解如何完成購買與收貨 | 購買步驟、已確認的付款／配送／自取條件與相關疑問 |
| 關於／品牌故事 | 理解品牌背景與歷史 | 經查證的創立背景、人物、沿革及品牌故事 |
| 購物袋 | 核對並調整選購內容 | 品項、數量、移除、小計、下一步 |
| 配送／結帳步驟 | 完成當前購買步驟 | 與本步驟相關的資料、核對、錯誤處理及下一步 |

非購物網站也按訪客任務分頁，不必套用電商頁型。路由名稱依網站慣例決定。

## 首頁與 Footer

- 首屏直接說明商品／服務為什麼值得選，用真實商品差異與證據支持；不以反問句或空泛情緒價值取代購買理由。
- 主標、區塊標題與主要按鈕不用「今天想吃哪一盤」「要怎麼選」等反問。先依 [賣點與行銷文案](marketing-claims.md) 確認客群與依據，再直接陳述理由與下一步；FAQ 與必要表單提問除外。
- Hero 只挑一個最值得推薦、可查證且對客群有意義的選擇理由，用短主標、主視覺與一個主要行動呈現；主標下可加一句簡短介紹，不塞長文或多項賣點。標語不任意插入換行，完整句依螢幕自然排版。商品形式、入數、用途等資訊不自動等於品牌選擇理由，應放在相關商品資訊。
- 刪去無助顧客決策的解釋，例如品牌名稱如何轉換、資料調查過程或製作網站的思路；品牌背景頁也只寫客群需要的資訊。
- 讓訪客快速看到少量熱賣商品並前往詳情。沒有銷售資料或店家確認時用「精選／推薦」，不可編造熱賣、銷量、排名或見證。
- 提供明顯的「查看全部商品／開始選購」入口，通往完整購物頁；首頁不代替完整型錄。
- 「怎麼買」「關於品牌」應連至獨立頁面，例如 `/how-to-buy`、`/about`，不使用 `/#how-to`、`/#about`。完整購買教學、歷史沿革及品牌故事不堆在首頁。
- Footer 可用一兩句介紹店家或品牌，附已確認的聯絡／營業資訊與必要連結；完整故事仍在獨立頁面。
- 優先使用品牌可用的真實商品、包裝與照片，記錄來源及使用權待確認事項。沒有素材才使用明確標記的示意，不把示意當真實產品。

## 實作前先列頁面表

每頁記錄：**URL、訪客任務、主要行動、必要內容與來源、不能混入的內容、入口／下一步、必要的空／錯誤等狀態**。

必要內容先按 [品牌調查與缺資料處理](brand-research.md) 查證。獨立頁面仍要有真實素材；缺資料就列待補欄位或先不開放，不能為了補頁數放空泛步驟與薄弱故事。

用一行寫出每頁要幫訪客完成的事。若同時出現兩個互不相干的任務，拆成兩頁。已知資訊直接沿用，只有真正影響方向的缺漏才向網站擁有者確認。

## 驗收

1. 每個內頁都能以一句話說出唯一任務，內容與操作均支持此任務。
2. 選購、購買說明、品牌故事是獨立頁面；主要導覽、Footer 及手機版連結一致，不再回首頁錨點。
3. 每個頁面 URL 都能直接開啟、重新整理及分享，且顯示正確內容；瀏覽器返回行為正常。
4. Hero 只呈現一個具體核心推薦點，文字精簡；首頁可快速進商品並找到完整購物頁，沒有完整品牌長文、購買教學或無助決策的解釋。
5. Footer 介紹簡短；價格、規格、熱賣與品牌主張均有資料支持，待確認的內容明確標示。
6. 在桌機與手機走過實際操作，驗證頁面分工、導覽與下一步；畫面好看或套用過通用 skill 都不能省略這項檢查。
