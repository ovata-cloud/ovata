# 網頁速度

做新頁面、改首頁或版型，以及每次上測試站前讀。顧客多半用手機看網站，頁面越重越慢；建置成功不代表網頁夠快。

## 圖片：一律要壓縮過的尺寸

媒體庫的圖片（`/api/media/uploads/…`）不帶參數時拿到的是上傳的原檔，手機截圖或相機照片常常一張 1–2 MB。網頁上顯示時一律加 `?w=寬度`，後端會給壓縮過的 WebP：

- 寬度用 160、320、480、640、960、1280、1920、2560；其他數字會取下一個較大的寬度，原圖較窄時不放大。
- `<img>` 用 `srcset` 列幾個寬度、`sizes` 寫圖片在版面上的實際寬度，讓瀏覽器依螢幕挑；`src` 放其中一個寬度。
- 依版面選寬度範圍：縮圖、頭像、購物袋小圖 160–480；商品卡、分類圖 320–960；滿版主視覺 640–2560。不要為了「保險」只給大圖。
- 不帶 `w` 的原檔只給下載或「看原圖」用。

```tsx
const WIDTHS = [320, 640, 960, 1280];
const sized = (src: string, width: number) =>
  src.startsWith('/api/media/uploads/') ? `${src}${src.includes('?') ? '&' : '?'}w=${width}` : src;

<img
  src={sized(photo, 640)}
  srcSet={WIDTHS.map((w) => `${sized(photo, w)} ${w}w`).join(', ')}
  sizes="(min-width: 1024px) 25vw, 50vw"
  width={600}
  height={800}
  loading="lazy"
  decoding="async"
  alt={name}
/>
```

- 網站自己放在 repo 的圖片（例如 `/images/hero.jpg`）沒有 `?w=`：提交前先壓成 WebP 或 JPG，寬度最多是顯示寬度的 2 倍，單張盡量 300 KB 以內。建置不會幫你壓縮。
- 首屏最主要的那張圖（通常是主視覺第一張）`loading="eager"`、`fetchPriority="high"`；其他圖片 `loading="lazy"`。輪播只有第一張先載，其他張用 lazy 或等第一張顯示後再載。
- 每張圖寫 `width`、`height`（或 CSS `aspect-ratio`），避免圖片載入時版面跳動。

## 頁面資料：只帶這一頁要用的

- 伺服器只把這一頁畫面需要的資料交給瀏覽器。不要在全站共用的 layout 讀整份商品目錄（全部商品、所有規格與說明），再當 props 傳給 client component：每一頁的 HTML 都會內嵌一整份，商品一多，連條款頁都有幾百 KB。
- 列表只帶卡片要顯示的欄位（名稱、價格、第一張圖、是否售完）；商品說明、完整規格與其他照片到商品頁再讀。商品多時分頁或「看更多」，不要一次全部載入。
- 一頁要的資料同時讀，不要讀完一個再讀下一個。分類的順序看列表裡每件商品的 `category.position`（它在自己分類裡第幾個）：讀一次全部商品就能排好每個分類，不要每個分類再查一次。
- 會一直用到的資料可以在伺服器短暫快取，但快取的仍然只是這頁要的資料。

## 字型與外部程式

- 中文字型檔很大：最多用兩個字族、只載會用到的字重。用 Google Fonts 時帶 `display=swap`；不要把整套中文字型檔放進 repo。
- 分析、聊天、社群嵌入等外部程式用 `async` 或等使用者互動後再載，不要擋住首屏。

## 上測試站前量一次

用手機尺寸（例如 390×844）開測試站的首頁、商品列表頁與商品頁，在瀏覽器開發者工具的 Network 看：

- 首頁總傳輸量盡量在 2 MB 以內，首屏圖片合計 300 KB 以內。
- 沒有單張超過 500 KB 的圖片；有的話找出是哪個區塊，改用 `?w=` 或先壓縮。
- HTML 本身（未壓縮）在 200 KB 以內；超過通常是頁面內嵌了太多資料。
- 有 PageSpeed Insights 或 Lighthouse 時看手機的 LCP，目標 2.5 秒以內。

量到的數字和修正記在網站 repo 的檢查紀錄裡；沒量過的頁面不要說已經檢查過速度。
