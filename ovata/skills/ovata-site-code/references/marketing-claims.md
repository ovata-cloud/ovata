# 賣點與行銷文案

用於重寫首頁、行銷頁或更新樣板。先決定顧客有理由選什麼，再寫版面上的字；同產業不同站也要各有自己的理由。

1. 讀需求中的 `selling_points`、`praise`、`proof`、商品和最新補充。舊需求沒有賣點欄位時，從已知商品、做法、公開品牌資料找。依 [品牌調查](brand-research.md) 核對來源與日期；競品只能參考結構，不移用其事實。
2. 拆開每個主張，記在網站 repo 的 `docs/selling-points.md`：客群、主張、來源與日期、等級、使用頁面。等級為已查證、客戶提供、待確認、不使用。沒有依據的最高級、療效、數字、得獎和見證不用。未找到公開來源不等於不實。
3. 選一個對客群重要、有依據且有差異的理由作 Hero。短主標、一句介紹、相關商品視覺與主要行動彼此呼應；其他規格與次要賣點放商品詳情或後續區塊。
4. 主標、區塊標題與行動文案採直接陳述，例如「布套拆下就能洗，睡窩好整理」，不用「牠睡覺是捲一團，還是攤一條？」或「今晚想吃什麼？」。真正的 FAQ 與必需的表單提問可以保留。
5. 計算器、時刻表、尺寸表、預覽和穿搭工具幫顧客選購；不要只因為網站有互動，就把它當成品牌最值得購買的理由。價格型理由須寫清楚適用品項、單位與估算基準，不能將其中一款的低價推廣成全系列承諾。
6. 虛構樣板使用明確標示的示範商品設定，記為「客戶提供（虛構示範設定）」，不得冒充已查證的真實品牌。樣板示範可以表現規格與流程，不能編造真實職人背書、客戶見證、認證與銷售成績。真實商家套用前應換成自己的資料。
7. 首頁只呈現理由、少量精選商品與獨立頁入口；完整選購、工具、購買說明和品牌故事各按 [頁面分工](page-structure.md) 處理。沒有銷售依據用「精選」，不用「熱賣」。

檢查桌機與手機：主標自然換行且在首屏可讀，主要行動到正確商品或獨立頁，理由與商品規格一致。待確認主張先不使用；其餘已知內容照常完成。
